The interface has grown module by module and it works, but it has no system underneath it. Before a fourth and fifth module land, it needs one — otherwise every new panel is a new negotiation and the whole thing slowly drifts.

## The look to avoid

The default appearance of a 2026 web app is a dark slate background, a grid of rounded cards, a violet-to-blue gradient, one grotesk at three weights, and a glassy panel with a blur behind it. It reads as *an AI product*. kosmos is not that. It should read as something between a well-set physics textbook and a bench instrument.

## Principles

- **The canvas is the subject.** Chrome sits at the edge and recedes. Nothing decorative competes with the data.
- **Numbers are typeset, not printed.** Tabular figures, aligned decimal points, units in a lighter weight, no raw float ever shown to a human.
- **Colour carries meaning only.** The plot palettes are the only saturated colour on screen; the interface itself is close to achromatic so the data can be the colour.
- **Hairlines, not boxes.** Space and thin rules separate things. Borders and shadows are the last resort, not the first.
- **One type scale.** A grotesk with actual character for the interface, a mono that aligns properly for values and formulas.
- **Motion explains or does not happen.** A transition may show where something came from. Nothing else moves. `prefers-reduced-motion` is honoured.
- **Light theme is not an afterthought.** Half of academia works in a bright room and prints on white paper, and the exports in #5 have to survive there anyway.

## Non-negotiable: no account, ever

Nothing in the interface may ask for a login, an email, or consent to a cookie. If a feature cannot work without one, it does not ship. State lives in the URL (#20) and in local storage the user can clear. This is a product boundary, not a phase.

## The token layer

One file of CSS custom properties: colour, type scale, spacing, radius, hairline, elevation, motion. A self-hoster rebrands by overriding one block. The SVG export (#5) reads the same tokens, so a figure and the screen agree.

## The primitives

Named against [the Component Gallery](https://component.gallery/components/) vocabulary so they are recognisable to anyone joining. Build only what the modules actually need, in this order:

**First** — Button, Button group, Segmented control, Toggle, Slider, Text input, Label, Fieldset, Separator, Stack, Badge, Tooltip
**Second** — Table, Tabs, Popover, Toast, Alert, Empty state, Skeleton, Spinner, Icon, Kbd
**Third** — Combobox, Search input, Select, Drawer, Modal, Stepper, Tree view, Progress bar, File upload

Skip link and Visually hidden come with #16.

## First run

The app currently opens with two seeded functions and no explanation. Replace that with a real **empty state**: one line saying what this is, three things to try as one click each, and the input already focused. A first-time visitor should have produced something within five seconds without reading anything.

Depends on nothing. Everything after it depends on this.
