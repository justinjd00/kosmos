Every view should be a URL, and that URL should contain the whole state — expressions, parameters, viewport, module, everything. Paste it into a paper, an email, a lecture slide, an issue tracker, and it opens exactly what the sender was looking at.

The current deep links carry a preset and a warm-up time. That is a start, not the thing.

## Constraints that shape the design

- **No account and no server.** The state goes in the URL fragment, compressed and base64url encoded, so it never leaves the browser — a fragment is not sent in the HTTP request at all. This is not a limitation to work around; it is the reason the feature can exist without a privacy policy.
- **Short enough to survive.** Mail clients and chat apps mangle long URLs. Compress hard, and when a state still will not fit, fall back to offering a downloadable `.kosmos` file rather than quietly creating a server-side store.
- **Forwards compatible.** A link made today must still open in two years. Version the payload and keep readers for old versions. A permalink that breaks is worse than no permalink.
- **Copy link is one visible action**, not something buried. It is the single most valuable thing a teacher or a co-author does with this tool.
