The graph and the periodic table are in place (`core/src/chem/`). This adds the numbers a chemist would actually quote, each computed from the parsed structure rather than looked up.

**In `core/src/chem/descriptors.rs`:**

| Quantity | Definition to follow |
|---|---|
| Molecular formula | Hill order: C first, then H, then everything else alphabetically |
| Average mass | Sum of `weight_micro`, respecting `Atom::isotope` where it is set |
| Monoisotopic mass | Sum of `mono_micro`, likewise |
| Exact mass of the ion | Monoisotopic mass minus `charge * 0.000548579909` (electron mass) |
| Degrees of unsaturation | `(2*C + 2 + N - H - X) / 2`, generalised over the elements present |
| Heavy atoms, rings, aromatic rings | Already available on `Molecule` |
| Rotatable bonds | Already available; add a test against published counts |
| Hydrogen bond donors | Lipinski: count of N-H and O-H hydrogens |
| Hydrogen bond acceptors | Lipinski: count of N and O atoms |
| Formal charge | Sum of `Atom::charge` |
| Fraction sp3 | sp3 carbons over all carbons |

Every value must carry the definition it used, because "hydrogen bond acceptors" means three different things in three different papers. Model that as a `Descriptor { name, value, unit, method }` so the interface and the CSV export can both show the provenance.

**Not in scope here:** logP. The Crippen atom typing is a large SMARTS table and getting it half right is worse than not shipping it — see #12.

**Tests:** published values for aspirin, caffeine, ibuprofen, glucose, paracetamol, alanine, nicotine, cholesterol. Formula and monoisotopic mass must be exact; nothing may be approximate that does not have to be.
